# 照片快筛 · 原生桌面版 3.1.0

适用于 Windows 10 / 11 64 位，使用 Qt Widgets 直接显示双图，不使用浏览器、WebView 或网页服务器。JPG、PNG、TIFF、HEIC 和多种相机 RAW 可以在同一资料库内筛选。为每天约十万张照片的筛选量设计：SQLite 索引、分页队列、独立解码进程、后台预读和有限内存缓存，十万张照片不会一次加载进内存。支持本机硬盘、移动硬盘和可访问的 NAS 路径。

界面参照 iPhone 照片 App 与 apple.com 的深色设计：纯黑底让照片成为主角，顶部是文件夹名称与“未筛选 / 保留 / 已删除”分段切换，下方是浮动操作条与缩略图条。

## 使用 APP

解压 **PhotoSieve-Windows-x64.zip** 到本机目录，双击 `PhotoSieve.exe`。保留整个文件夹及 `_internal`，不能只复制 EXE。APP 已包含 Python、Qt、RAW 和 HEIC 解码依赖，无需安装 Python。

点击“打开文件夹…”，或把文件夹直接拖进窗口，会自动扫描（包括子文件夹）。以后打开 APP 会回到上次的文件夹和筛选位置；文件夹有新照片时，在右上角“⋯”菜单选“重新扫描当前文件夹”。

| 操作 | 结果 |
|---|---|
| ↑ | 保留左图，立即显示下一张 |
| ↓ | 删除左图（移入暂存），立即显示下一张 |
| → 或图片上右键 | 下一张，不修改筛选结果 |
| ← | 恢复最近一次删除，即使之后保留过其他照片 |
| Ctrl+Z | 撤回最近一次筛选或删除 |
| 按住 ↑ / ↓ / → | 按键盘重复速度连续筛选（Windows 默认每秒约 30 张） |
| 单击图片，或 Z | 在原位平滑放大到 100%；RAW 读取完整画幅 |
| 放大后拖动 | 查看其他区域，拖动不会退出放大 |
| 再点一次图片，或 Esc | 平滑还原双图 |

按键后界面立即切到下一张，保留记录与文件移动在后台按顺序写入；如果写入失败（例如硬盘断开），照片会回到队首并显示原因。左图预览尚未读出时不会被筛选，图片会轻轻晃动提示稍等，避免删除没看到的照片。

动效：保留时左图上浮淡出，删除时下沉淡出，下一张从右侧滑入原位，新照片淡入；连续按键或按住方向键时自动跳过动画，保证速度。

## 删除文件在哪里

↓ 会把照片移入**该照片原文件夹下的 `.photo-sieve-trash`**，这不是 Windows 回收站。原文件名和路径记录在资料库中，暂存文件名使用随机编号避免冲突。在“已删除”视图里双击照片，或选中后点“恢复所选”，即可放回原位置；悬停可以看到原路径和暂存路径。

暂存照片仍占用磁盘空间，APP 不会永久清空暂存目录。手工删除 `.photo-sieve-trash` 或资料库会影响恢复，请保留它们，直到确定筛选完成。恢复遇到原位置已有同名文件会报告冲突，不覆盖。重启程序后仍可以恢复。

## 导出保留照片

点击右上角“导出”，选择目标文件夹：

- **复制**：保留原片，把副本放入目标文件夹。
- **移动**：原片转到目标文件夹，成功的照片从资料库移除；此操作不能用 ← 撤回。

导出包含任务开始时的全部保留照片，保留原文件名和子文件夹，遇到已存在的目标文件不会覆盖，会继续处理其他照片并报告失败原因。再次打开导出窗口可以查看上次的成功、失败数量，并在资源管理器中打开。

## 资料库与旧版本

默认资料库在 `%USERPROFILE%\.photo-sieve`；旧版本的保留记录、删除记录、缓存和设置都会自动沿用，不需要迁移。旧版本如果用过自定义 `--data-dir`，新 APP 也需指定同样路径：

```bat
PhotoSieve.exe --data-dir "D:\筛选记录" --folder "J:\照片"
```

打开不同的照片文件夹会为其使用独立的资料库，原文件夹的记录仍保存在 `%USERPROFILE%\.photo-sieve\libraries`。请保持照片文件夹路径稳定；拔掉外接盘后连接原盘，再重新扫描。

## 性能

- **解码在独立进程中进行**：原片解码（JPEG、HEIC、RAW）交给后台解码进程，数量为 CPU 核数减 1（2 到 8 个），优先级低于界面，因此界面在大量解码时仍然流畅；某个损坏文件让解码器崩溃，也只影响那一张照片。如果系统阻止创建子进程，会自动退回线程解码。
- **预读**：内存中保留后面 24 张按窗口大小解码好的预览；磁盘上提前生成后面约 1,200 张照片的预览（受缓存额度限制）。看照片时停顿，后台就会继续往后预读。
- **RAW**：日常浏览使用相机嵌入的预览，速度很快；放大到 100% 时才解码完整画幅。RAW 色彩由 LibRaw 处理，可能与相机或厂商软件不同；新机型支持取决于 LibRaw。HEIC 通过 pillow-heif 解码。
- **缓存**：磁盘 JPEG 预览缓存默认上限约 2 GB，可用 `PhotoSieve.exe --cache-mb 8192` 调大，从而预读得更远。APP 不会改写原图。

以下数据在 4 核云端测试机上测得（Linux 离屏渲染，模拟每秒 40 次按键）：

| 场景 | 结果 |
|---|---|
| 预读完成后按住 ↓ 或 ↑ | 每秒 40 张，全部按键被接受、每张都实际显示；按键处理中位数约 1 毫秒 |
| 未预读的 Sony A7 III RAW（25 MB），每秒 20 张 | 全部跟上，每张都实际显示 |
| 未预读的 Sony A7 III RAW，每秒 40 张 | 约 36 张 / 秒，97% 的照片实际显示 |
| 未预读、细节极多的 2400 万像素 JPEG（14 MB） | 约 11 张 / 秒，受 CPU 解码速度限制；核数越多越快 |
| 连续 3,000 张 | 内存稳定在约 460 MB，无增长 |
| 十万张资料库 | 扫描约 2.6 秒；保留约 2 毫秒、删除约 5 毫秒、恢复约 2 毫秒一张；状态刷新约 17 毫秒 |

读取速度取决于照片大小、编码、CPU 核数、硬盘和 NAS；网络盘上的首次读取会更慢。`tools/stress_check.py` 与 `tools/scale_check.py` 可在自己的电脑上重新测量。

## 从源码运行或重新打包

需要 64 位 Python 3.11 或更新版本。Windows 双击 `start_windows.bat` 安装依赖并运行。程序员也可执行：

```bat
python -m pip install -r requirements-desktop.txt
python desktop.py
```

Windows 双击 `build_windows.bat`，会在独立构建环境内安装依赖，生成 `dist\PhotoSieve\PhotoSieve.exe` 和 `PhotoSieve-Windows-x64.zip`。使用目录形式发布，避免每次启动时解压大型依赖。发布包包含源码和依赖的开源许可证；本项目源码为 MIT。

代码结构：`desktop.py` 为窗口与筛选流程，`widgets.py` 为照片视图、过渡与提示等组件，`theme.py` 为颜色、样式与动效曲线，`app.py` 为资料库、解码与文件操作。

## 验证

- `python -m unittest discover -s tests -p "test_*.py"`：数据迁移、删除与持久恢复、文件冲突、解码进程、完整尺寸解码、HEIC、缓存、导出和更新器。
- `QT_QPA_PLATFORM=offscreen python tests/desktop_check.py`：真实 Qt 控件上的双图、↑↓←→、Ctrl+Z、连续按键、写入失败回滚、就地放大与还原、缩略图条、保留视图、导出、拖入文件夹和跨分页连续删除。
- `QT_QPA_PLATFORM=offscreen python tools/stress_check.py --rate 40 --megapixels 24`：按住按键的压力测试（`--source 某个RAW文件` 测试指定相机格式，`--idle 30` 模拟先停顿预读）。
- `python tools/scale_check.py`：十万张资料库的扫描、查询与筛选操作耗时。

GitHub Actions 在 Windows 上运行单元测试、原生界面检查和更新检查，打包后再运行 EXE 自检（包括解码进程）与完整更新流程。

## GitHub 公开仓库与自动更新

源码仓库：https://github.com/Quietime/photo-sieve 。
正式版本：https://github.com/Quietime/photo-sieve/releases/latest 。

公开仓库更新无需 GitHub 登录、授权或令牌。默认启动时检查正式版本，后台下载并验证 SHA256 和安装文件清单；下载完成后右上角“⋯”出现蓝点。下载时仍可筛选；扫描、导出和筛选记录写入完成且停止操作 30 秒后，自动关闭、替换 APP 自身文件并重新启动。也可以在“⋯”菜单选择“立即安装更新并重启”，或关闭“自动更新”后手动检查。照片、筛选数据库、删除暂存区不会清空。替换失败会尝试恢复旧版；更新目录保留旧版文件备份和结果。

APP 目录需要当前用户可写，建议解压到本机普通文件夹。更新需要 GitHub 网络连接；失败会显示状态，原版继续可用。GitHub 无登录 API 有请求次数限制，遇到限制可稍后重试。

### 发布下一版

修改程序后，在 `version.py` 提高 `APP_VERSION`（例如 `3.1.1`），更新 `RELEASE_NOTES.md`，提交并推送 `main`。GitHub Actions 自动在 Windows 上测试、打包、验证完整 EXE 更新流程，然后创建对应 tag 和 Release，并上传 ZIP、`update.json` 与 SHA256 清单。已发布版本不覆盖；仅改代码而不提高版本会运行构建验证，但不会发布另一个同版本包。

本地发布也可运行 `build_windows.bat`，产物在 `release/`。不要上传照片、数据库、缓存或 GitHub 令牌；`.gitignore` 已排除常见本地数据与构建文件。

# 照片快筛 · 原生桌面版 3.0.1

适用于 Windows 10 / 11 64 位，使用 Qt Widgets 直接显示双图，不使用浏览器、WebView 或网页服务器。JPG、PNG、TIFF、HEIC 和多种相机 RAW 可以在同一资料库内筛选。针对大量照片采用 SQLite 索引、分页队列、后台读取与有限预加载；十万张照片不会一次加载进内存。支持本机硬盘、移动硬盘和可访问的 NAS 路径。

## 使用 APP

解压 **PhotoSieve-Windows-x64.zip** 到本机目录，双击 `PhotoSieve.exe`。保留整个文件夹及 `_internal`，不能只复制 EXE。APP 已包含 Python、Qt、RAW 和 HEIC 解码依赖，无需安装 Python。每次启动时顶部文件夹路径输入框为空；原照片和资料库中的筛选记录不会清空。选择照片文件夹后点击“扫描 / 更新目录”。扫描包括子文件夹，完成后开始筛选。

| 操作 | 结果 |
|---|---|
| ↑ | 保留左图，然后继续；该照片从下方列表移除 |
| ↓ | 删除左图，然后继续；可在“已删除”查看 |
| ← | 恢复最近一次删除，即使之后保留过其他照片 |
| → 或图片区域右键 | 下一张，不修改筛选结果 |
| Ctrl+Z | 撤回最近一次筛选或删除 |
| 单击左右任一图片，或 Z | 直接在该图片区域放大；后台读取原始分辨率，RAW 解码完整画幅 |
| 放大后拖动 / 滚动条 | 查看其他区域，拖动不会退出放大 |
| 再点一次图片，或 Esc | 恢复双图显示，不关闭 APP |

默认显示“未筛选”，已保留的照片可在“保留”页面查看，但不会出现在下方列表。← 在队列已空时仍可以恢复。窗口内“上一张”按钮用于回看，左方向键专用于恢复删除。对话框和目录输入期间不会误操作照片。

## 删除文件在哪里

↓ 会把照片移入**该照片原文件夹下的 `.photo-sieve-trash`**，这不是 Windows 回收站。原文件名和路径记录在资料库中，暂存文件名使用随机编号避免冲突。“已删除 · 可恢复”页面显示每张照片的预览、原路径、实际暂存路径，并提供逐张恢复和打开暂存目录。顶部也显示最近一次删除及其暂存路径。

暂存照片仍占用磁盘空间。APP 不会永久清空暂存目录。手工删除 `.photo-sieve-trash` 或资料库会影响恢复，请保留它们，直到确定筛选完成。恢复遇到原位置已有同名文件会报告冲突，不覆盖。重启程序后可以继续恢复。

## 将保留照片保存到新文件夹

点击“复制 / 移动保留照片…”，选择目标目录：

- **复制全部保留照片**：保留原片，把副本放入目标目录。
- **移动全部保留照片**：原片转到目标目录，成功的照片从源资料库移除；此操作不能使用 ← 撤回。

导出包含任务开始时的全部保留照片，不只是屏幕上两张。保留原文件名和相对目录，遇到已存在的目标文件不会覆盖；会继续处理其他照片并报告失败原因。完成后再次打开该窗口可以查看成功、失败数量和目标路径，直接打开输出目录。同一磁盘移动通常只修改目录记录，跨磁盘移动则需要复制文件内容。请等任务完成后退出。

## 原版本升级

关闭旧版浏览器后台的 Python 控制台，然后运行桌面 APP。默认资料库仍在 `%USERPROFILE%\.photo-sieve`；原有保留记录、删除记录和缓存会自动沿用。不要删除这个目录。旧版本如果用过自定义 `--data-dir`，新 APP 也需指定同样路径：

```bat
PhotoSieve.exe --data-dir "D:\筛选记录" --folder "J:\照片"
```

APP 内选择不同的照片目录会为其使用独立的资料库，原目录记录仍保存，重启会回到最近使用的资料库，但路径输入框留空。默认库兼容旧版本；其他目录资料库在 `%USERPROFILE%\.photo-sieve\libraries`。请保持照片目录路径稳定；拔掉外接盘后连接原盘，再更新扫描。

## 性能与格式

图片读取和解码在后台线程进行，元数据按约 40 张分页，提前读取后面约 6 张预览，内存最多缓存 16 张普通预览。底部显示的 16 张照片均单独加载缩略图，不再只显示前 6 张；未完成时显示“读取中”，失败时显示原因。小尺寸缩略图缓存最多 64 张，待处理缩略图和原图请求均有数量上限。磁盘 JPEG 缓存默认上限约 2 GB；清理在后台运行。缩略图复用预览缓存，删除采用同目录暂存，避免每张复制大文件。原始分辨率只在用户打开对焦检查时解码，不预加载大图。

RAW 的常规预览优先使用嵌入预览，全尺寸对焦检查则解码原始画幅，并在当前图片区域替换预览；整个过程不会新增图片窗口。RAW 色彩由 LibRaw 处理，可能与相机或厂商软件不同；具体新机型支持情况取决于 LibRaw。HEIC 通过 pillow-heif 解码。损坏或无法解码的照片显示原因并进入“预览异常”。读取速度取决于照片大小、编码、硬盘和 NAS，原生界面不会消除这些耗时。

可以指定缓存额度，例如 `PhotoSieve.exe --cache-mb 4096`。原图在复制导出时保留完整文件内容和时间戳；APP 对普通图和 RAW 的缩小预览都不会写回原图。

## 从源码运行或重新打包

需要 64 位 Python 3.11 或更新版本。Windows 双击 `start_windows.bat` 安装依赖并运行原生界面。程序员也可执行：

```bat
python -m pip install -r requirements-desktop.txt
python desktop.py
```

Windows 双击 `build_windows.bat`，会在独立构建环境内安装依赖，生成 `dist\PhotoSieve\PhotoSieve.exe` 和 `PhotoSieve-Windows-x64.zip`。使用目录形式发布，避免每次启动时解压大型依赖。发布包包含源码和依赖的开源许可证；本项目源码为 MIT。

`app.py` 和 `static/` 保留为旧版本兼容与接口测试使用；原生 APP 的入口是 `desktop.py`，不会启动 HTTP 端口。

## 验证

`python -m unittest discover -s tests -p test_app.py` 验证数据迁移、删除与持久恢复、文件冲突、完整尺寸解码、HEIC、缓存和导出。`QT_QPA_PLATFORM=offscreen python tests/desktop_check.py` 验证真实 Qt 控件上的双图、↑↓←、Ctrl+Z、就地放大与恢复、完整缩略图列表、空的启动路径输入框、保留列表、原生导出窗口和连续删除跨分页。

十万条合成记录的索引分页测试及小图片连续删除测试用于检查队列结构和回归，不代表十万张实际 RAW 的吞吐量。Windows 构建通过 Wine 的 Windows Python 生成，兼容层启动检查不等同于在真实 Windows 硬件上的完整测试。

## GitHub 公开仓库与自动更新

源码仓库：https://github.com/Quietime/photo-sieve 。
正式版本：https://github.com/Quietime/photo-sieve/releases/latest 。

首次手动下载 3.0.1 并解压，之后可以在 APP 内检查更新。公开仓库更新无需 GitHub 登录、授权或令牌；“更新设置…”可以关闭自动更新。

默认启动时检查正式版本，后台下载并验证 SHA256 和安装文件清单。下载时仍可筛选；扫描、复制、移动等操作完成且停止操作 30 秒后，自动关闭、替换 APP 自身文件并重新启动。也可以点击“立即安装更新并重启”。关闭自动更新选项后仍可手动检查和安装。路径输入框仍在启动时留空，照片、筛选数据库、删除暂存区不会清空。替换失败会尝试恢复旧版；更新目录保留旧版文件备份和结果。

APP 目录需要当前用户可写，建议解压到本机普通文件夹。更新需要 GitHub 网络连接；失败会显示状态，原版继续可用。GitHub 无登录 API 有请求次数限制，遇到限制可稍后重试。

### 发布下一版

修改程序后，在 `version.py` 提高 `APP_VERSION`（例如 `3.0.2`），更新 `RELEASE_NOTES.md`，提交并推送 `main`。GitHub Actions 自动在 Windows 上测试、打包、验证完整 EXE 更新流程，然后创建对应 tag 和 Release，并上传 ZIP、`update.json` 与 SHA256 清单。已发布版本不覆盖；仅改代码而不提高版本会运行构建验证，但不会发布另一个同版本包。仓库需要启用 Actions 并有可用运行额度。

本地发布也可运行 `build_windows.bat`，产物在 `release/`。不要上传照片、数据库、缓存或 GitHub 令牌；`.gitignore` 已排除常见本地数据与构建文件。

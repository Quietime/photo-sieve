# 照片快筛：页面优化方案

日期：2026-10-23。范围是现有 Python/PySide6 桌面应用；本次交付方案和独立交互原型，不修改筛选、评级或文件处理逻辑。

## 推荐方向

**演唱会连拍的高速筛选工作台：照片先被看见，操作一眼可辨；灰色背景降低干扰，深蓝玻璃只承担导航和操作层级。**

保留已确认的灰底、深蓝、液态玻璃、左右 2:1 筛选布局，以及分级页可拖动分隔线。改进的重点是信息架构、字号、间距、照片/人脸/参数同步和交互连续性。没有新增营销横幅、统计卡片、头像导航或装饰性循环动画。

产品清单：本地照片与 ARW；一万多张连拍；未筛选/保留/已删除；左右对比；当前照片的人脸裁切；光圈/快门/ISO/焦距/拍摄时间；写入原图的星级；独立评级图库；后台缓存；云端装饰包；Windows 高刷新率显示器。

每页首先回答一个问题：

- 筛选：当前这张是否保留？左图是唯一决策对象。
- 分级：同一组照片中哪张值得更高星级？图库与大图形成稳定对应。
- 保留/已删除：有哪些照片，当前在看哪一张？单图相册与筛选工作流区分。
- 设置：当前调整影响筛选、分级，还是整个应用？范围必须看得懂。

## 筛选页

```text
应用标识 / 文件夹        照片筛选 · 照片分级       打开文件夹 · 设置
未筛选 / 保留 / 已删除                         左图为当前照片
┌──────────── 左侧 2/3 ────────────┐ ┌── 右侧 1/3 ──┐
│ 当前照片                         │ │ 下一张·仅供对比 │
│                                 │ │   较小的对比图  │
│                                 │ │ 人脸    当前参数│
└─────────────────────────────────┘ └───────────────┘
                可选：保留 / 删除 / 恢复 / 下一张
全部照片缩略条，自适应横竖比例，水平滚动条始终可找到
```

右图区域仍占1/3，但照片的最长边目标约为左图的60%，防止横图/竖图混排时右图反而更抢眼。右图标签有独立空间；不盖在人像上、不显示右图文件名。人脸与参数均来自左图，参数标题不重复相机品牌长串。

右/下快捷键保持保留/删除；顶部相册不接受方向键切换。重复按键随时生效，不等待胶囊选中动画结束。保留和已删除点击照片进入单图，空白边缘返回图库，点图按点击位置放大。

删除区继续保留用户已要求的多选恢复、全选/多选“从磁盘永久删除”；这属于独立批量选择状态，危险操作确认对象和数量。**不新增“一键清空”**。方案原型的相册只演示浏览，不连接磁盘。

## 分级页

```text
应用标识             照片筛选 · 照片分级            设置
范围 [全部照片]  星级 [全部星级]       更多筛选 · 选片工具
图库 / 缩略图大小      可拖动分隔线       当前预览
横竖照片同高居中                           大图
一行文件名 + 一行星级                   星级 / 自动下一张
纵向滚动                               人脸在左 / 参数在右
```

左右初始比例建议55:45，沿用用户记住的比例优先；最小宽度限制两端可读。拖动期间只改变布局，后台照片/人脸任务不被反复重启。松开后更新清晰预览目标尺寸。分隔线增加9px命中区，键盘左右键可微调，双击恢复默认可作为后续项。

同一尺寸档同时调整图片区域、单元格内边距、行距，避免只缩图但文字/空白仍占原高度。图片在固定高度里等比完整显示，横图居中，不因宽高比例变化顶齐。默认紧凑档目标在1440×900下完整容纳至少3行文件名与星级；具体列数随分隔线和缩略图滑块变化，不硬锁3×5。

Ctrl+滚轮只在左图库内调整图块；普通滚轮按较小步幅纵向移动。评级1–5、0清除、左右浏览；星级视觉立即反馈，后台写入后另行反馈成功/失败。不能把“界面已更新”误报为“原图已写入”。

## 设置、启动与异常状态

- 入口保留在右上角，但展示有清晰分类的设置页/独立原生面板；不再依赖一个长滚动菜单承载所有项目。
- 照片筛选、照片分级各自保存操作栏、快捷键、动态效果和帧率偏好。缓存/GPU/更新/日志属于应用级。设置附近明确说明作用范围。
- 未打开文件夹：打开文件夹、继续上次进度。打开后：只保留当前工作内容；继续上次进度入口隐藏。
- 导入中：真实扫描数量/阶段 + 两端圆角进度条；未知总数时明确说“正在扫描”，不伪造百分比。
- 无人脸：不保留上一张的人脸，不制造空壳卡片；参数可保留同一对齐位置。
- 元数据缺失：显示“未记录”或省略该字段，不显示上一张的值。
- 照片/人脸未就绪：后台继续准备，当前对象身份明确；不把旧脸、旧参数暂留在新照片上。
- 缓存保持已确认规则：当前文件夹的非删除照片在后台预览和识别；10GB上限；换文件夹清理之前缓存。方案不改变该规则。
- 更新提示只列版本、3条以内主要变化、下载与更新、稍后；详细日志可展开。关闭确认突出“保留进度并关闭”，其他选择降低强调。
- 云端装饰包：显示来源/版本、下载和导入阶段、失败重试。主题包不改变照片色彩与原始图像。

## 动效与性能预算（目标，非实测保证）

| 对象 | 建议行为 |
|---|---|
| 当前照片、人脸、参数、星级 | 已缓存内容在同一界面提交中更新，不用入场动画拖延 |
| 按压与悬停 | 沿用80/120ms；不挪动周围排布 |
| 顶部分段高亮 | Motion Prompt #060 的250ms cubic过渡；内容立即切换；新操作可中断 |
| 菜单/设置轻过渡 | 120–160ms，减少动态效果时关闭；不用800ms滚动入场 |
| 点击放大 | 以指针位置为中心，复用清晰纹理；连续点击能随时反向 |
| 拖动分隔线 | 跟随指针；不叠加另一段尺寸补间动画 |
| 240Hz | 实机目标每帧约4.17ms；60/120Hz约16.67/8.33ms。浏览器原型不能证明Windows真机达到240fps |

后续在Windows实机分别记录输入到呈现、快速连切、分隔线拖动和长时间图库滚动的p95/p99；需要真实ARW与240Hz设备。没有把本地浏览器原型标成生产性能测试。

## 预览与边界

启动 `design-lab` 的Vite服务后打开 `/proposal/`。可切换三页、背景/密度/玻璃/各模式操作栏、示例相册、Ctrl+滚轮调图、拖动或键盘调分隔线、数字键评级与点击放大。

素材：已有公开NASA宇航员示例素材的不同裁切，仅用于展示横竖布局，不是用户的照片。18条演示记录由一个JS数据集生成，计数来自记录状态；不代表真实导入、识别或评级数据。该示例素材的f/2.8等相机参数是明确的**排版示例值，不是NASA照片的真实EXIF**。

优先实施顺序：
1. P0：分级筛选层级、可读性、设置范围；围绕真实现有控件改动。
2. P1：图库密度、辅助区域自适应、连续放大/分隔线的交互统一。
3. P2：材质细节与装饰包界面；沿用已经实现的渐进模糊缓存。

验收：1280×800、1440×900、1920×1080，Windows125%/150%/200%缩放；横竖混合、长文件名、无人脸、元数据缺失；按住保留/删除/撤销；数字评级失败回滚；两个模式的设置互不影响。仅改动哪些控件就运行对应测试，文件删除与ARW写入的改动再执行专门回归。

## 本次验证结果

- 源码检查：Taste app lint，0 FAIL、0 WARN。
- 浏览器实测：1440/1280/768/390四种宽度，三页均无页面水平溢出；12项针对性交互检查通过。
- 检查包括方向键→保留而不切换相册、撤销、两个模式操作栏独立、数字键/点击评级、拖动与键盘调分隔线、空筛选不显示旧预览、重复放大、减少动态效果。
- Taste rendered inspector：0 FAIL、1 WARN。唯一的palette-cream警告指向保留的`#F4F0E6`象牙白文字，而非页面背景；这是既有主题和用户配色要求，保留并记录为例外。
- 四种宽度的截图已逐页生成；桌面筛选/分级/设置与390px预览已实际查看，图库采用固定图高、横竖等比完整展示。原型预览并不是Qt在手机上的运行能力承诺。
- 独立HTML采用内嵌CSS、JS和图片；以隔离浏览器文档验证页面切换与键盘评级，不需要Vite或外部网络。file://导航被本环境浏览器策略阻止，未验证这种打开方式。
- 既有11px提示色`#918F88`在`#303236`上的对比度详见`evidence/contrast.json`；主文字、辅助文字、选中控件和删除控件也分别计算，没有只凭肉眼判断。
- 未运行桌面全量测试或发布安装包，因为本次没有改动生产应用；这是一份可评审的方案与独立原型。
